# Reflection (300–400 words)

Using semantic HTML gave this project a structure that is meaningful beyond its visual appearance. Elements such as `header`, `nav`, `main`, `article`, `aside`, and `footer` describe the purpose of each region. A screen-reader user can understand the page as a set of landmarks instead of hearing one long collection of generic containers. The shared header and navigation also make the four pages feel like one website, while the skip link gives keyboard users a direct route to the main content.

The heading outline helped me plan each page before writing its content. A clear `h1` identifies the page topic, and lower-level headings divide the information into related sections. This is more useful than choosing heading tags only because of their default font size. The schedule table also benefits from semantic markup. Its caption explains the table, and header cells use `scope` so the relationship between a time, day, and session is clearer. The `rowspan` and `colspan` attributes represent real timetable groupings rather than being added only to satisfy a requirement.

The registration form uses labels, fieldsets, and legends to make controls understandable. Native input types and validation attributes provide useful browser feedback, while optional fields are kept optional. The form does not ask for a home address, date of birth, password, government identification, payment information, or health details. Those details are not needed to demonstrate course registration. Collecting unnecessary personal information would increase privacy risk without improving the purpose of the form. The phone number and portfolio link are also optional because a student should be able to express interest without providing extra contact details or an online profile.

One limitation is that this mini-site is a front-end demonstration rather than a complete university registration system. The local form endpoint is only for observing submitted name-value pairs during testing; it does not permanently store registrations. Before real use, the course team would need an approved, secure service and a clear privacy notice. Overall, semantic markup made the site easier to navigate, test, maintain, and understand for people using different devices and assistive technologies.
